# G-Code Commenter Extension - Development Specification

## Overview
Create a new installable CNC extension that intercepts g-code generated by the built-in 'svg-parser' plugin and prepends a comment to it.

## Extension Details

### Name
**G-Code Commenter**

### Version
1.0.0

### Description
Automatically prepends a custom comment to g-code generated by the SVG parser, helping users identify code that has been processed through the extension system.

## Functional Requirements

### Primary Functionality
1. **Intercept g-code output** from the built-in svg-parser plugin
2. **Prepend a comment** to the beginning of the generated g-code:
   ```gcode
   ; Injected from G-Code Commenter Extension
   ```
3. **Preserve all original content** - the g-code must remain functionally identical
4. **Maintain injection behavior** - continue inserting into the target edit field as expected

### Scope
- Only affects g-code generated by the svg-parser plugin
- Does not modify g-code from other sources (manual entry, file loads, etc.)
- Should be transparent to the end user (aside from the added comment)

## Technical Requirements

### Extension Architecture
- **Type**: Installable service plugin (not built-in)
- **Installation**: Must follow the standard extension installation procedure
- **Configuration**: Should support enable/disable functionality
- **Dependencies**: Works alongside the built-in svg-parser plugin

### Implementation Approach

#### 1. Hook Identification
- **Event**: `gcode:generated`
- **Source**: svg-parser
- **Payload**: `{ source: 'svg-parser', payload: { gcode: string, filename?: string } }`

#### 2. Interception Mechanism
- **Technology**: RxJS Observable streams
- **Pattern**: Subscribe → Filter → Transform → Emit

```typescript
events
  .on('gcode:generated')          // Subscribe to event
  .pipe(
    filter(e => e.source === 'svg-parser'),  // Only svg-parser
    map(e => prependComment(e))              // Transform
  )
  .subscribe(e => events.emit('gcode:modified', e))  // Re-emit
```

#### 3. Content Modification
- Prepend comment line to g-code string
- Ensure proper line breaks are maintained (Unix `\n`)
- Validate g-code structure remains intact
- Add metadata to payload: `modified: true, modifiedBy: 'gcode-commenter'`

#### 4. Integration
- Uses RxJS operators for clean event handling
- No global state pollution
- Proper subscription cleanup on deactivate
- Configuration hot-reloading support

## How the Interception Works

### High-Level Overview

```
User Action: Parse SVG
       ↓
svg-parser processes file
       ↓
Emits 'gcode:generated' event
       ↓
Event Bus broadcasts to subscribers
       ↓
[G-Code Commenter subscribes]
       ↓
Filters for svg-parser events only
       ↓
Prepends comment to g-code
       ↓
Emits 'gcode:modified' event
       ↓
G-Code Editor receives modified code
       ↓
User sees commented g-code
```

### Technical Details

**Event Subscription:**
```typescript
events.on('gcode:generated')
```
- Returns an RxJS Observable
- Emits events as they occur
- Non-blocking, asynchronous

**Filtering:**
```typescript
.pipe(filter(event => event.source === 'svg-parser'))
```
- Only processes events from svg-parser
- Ignores other sources
- Prevents unwanted modifications

**Transformation:**
```typescript
.pipe(map(event => ({
  ...event,
  payload: {
    ...event.payload,
    gcode: `${comment}\n${event.payload.gcode}`
  }
})))
```
- Creates new event object
- Prepends comment to g-code
- Preserves all other event data

**Re-emission:**
```typescript
.subscribe(modifiedEvent => {
  events.emit('gcode:modified', modifiedEvent.payload);
})
```
- Emits modified event
- Downstream listeners receive it
- Original event still available to other subscribers

### Why This Approach?

**Advantages:**
1. **Non-blocking** - Doesn't stop other event handlers
2. **Composable** - Multiple extensions can process same event
3. **Testable** - Each step can be tested independently
4. **Maintainable** - Clear, functional code flow
5. **Safe** - No global state mutation

**Alternatives Considered:**

❌ **Monkey Patching:**
- Fragile, breaks with updates
- Hard to debug
- Unpredictable execution order

❌ **Direct Function Wrapping:**
- Tight coupling to svg-parser
- Not extensible
- Can't be disabled at runtime

✅ **Event-Based (Chosen):**
- Loose coupling
- Highly extensible
- Runtime enable/disable
- Clean architecture

## Troubleshooting Guide

### Issue: Comment Not Appearing

**Symptoms:** SVG parses but no comment added

**Possible Causes:**
1. Extension disabled
2. Event name mismatch
3. Source filter excluding event

**Solutions:**
1. Check Extensions view, enable if needed
2. Verify event name: `gcode:generated`
3. Check event source: must be `'svg-parser'`

### Issue: Multiple Comments

**Symptoms:** Comment appears multiple times

**Possible Causes:**
1. Multiple extension instances
2. Event re-emission loop
3. Configuration error

**Solutions:**
1. Check only one instance installed
2. Verify re-emission logic
3. Reset configuration to defaults

### Issue: Performance Degradation

**Symptoms:** Slow SVG parsing

**Possible Causes:**
1. Very large SVG files
2. Multiple extensions processing same event
3. Inefficient string operations

**Solutions:**
1. Optimize for large files (future enhancement)
2. Disable other extensions temporarily
3. Profile string operations
