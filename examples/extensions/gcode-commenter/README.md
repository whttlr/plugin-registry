# G-Code Commenter Extension

Automatically prepends identification comments to g-code generated by the SVG parser.

## Overview

This extension intercepts g-code output from the built-in `svg-parser` and adds a comment at the beginning to help identify code that has been processed through the extension system.

### What It Does

When you parse an SVG file to generate g-code, this extension automatically adds:

```gcode
; Injected from G-Code Commenter Extension
G21 ; Set units to millimeters
G90 ; Absolute positioning
...rest of your g-code...
```

## Features

- ✅ **Automatic commenting** - No manual intervention required
- ✅ **Non-destructive** - Original g-code functionality preserved
- ✅ **Configurable** - Customize comment text, add timestamps, filenames
- ✅ **Transparent** - Works seamlessly with existing workflow
- ✅ **Source-specific** - Only affects svg-parser output

## Installation

### Prerequisites

- Whttlr CNC Controls application installed
- Node.js and npm (for building from source)

### Option 1: Install from NPM (Recommended)

```bash
npm install @whttlr/gcode-commenter
```

### Option 2: Install from Source

```bash
# Clone or download this extension
cd gcode-commenter

# Install dependencies
npm install

# Build the extension
npm run build

# The built extension will be in the dist/ folder
```

### Option 3: Install in Whttlr App

1. **Copy to extensions directory:**
   ```bash
   cp -r gcode-commenter ~/Library/Application\ Support/com.whttlr.cnc-controls/extensions/
   ```

2. **Restart Whttlr CNC Controls**

3. **Verify installation:**
   - Open the Extensions/Plugins view
   - Look for "G-Code Commenter" in the list
   - Ensure it's enabled

## Usage

### Basic Usage

1. **Enable the extension** (if not already enabled)
   - Go to Extensions view
   - Find "G-Code Commenter"
   - Toggle to enabled

2. **Use SVG parser as normal**
   - Load an SVG file
   - Parse it to g-code
   - The comment will automatically be prepended

### Configuration

The extension can be configured through the plugin state API:

```javascript
{
  "commentText": "; Injected from G-Code Commenter Extension",
  "enabled": true,
  "includeTimestamp": false,
  "includeSvgFilename": false
}
```

#### Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `commentText` | string | `"; Injected from G-Code Commenter Extension"` | The comment to prepend |
| `enabled` | boolean | `true` | Whether the extension is active |
| `includeTimestamp` | boolean | `false` | Add generation timestamp to comment |
| `includeSvgFilename` | boolean | `false` | Add source SVG filename to comment |

#### Example with All Options Enabled

```gcode
; Injected from G-Code Commenter Extension
; Generated: 2025-10-30T18:45:23.456Z
; Source: my-design.svg
G21 ; Set units to millimeters
...
```

### Updating Configuration

Through the plugin API:

```javascript
// Get the plugin state service
const pluginState = await state.forPlugin('com.whttlr.gcode-commenter');

// Update configuration
await pluginState.update({
  commentText: "; Custom comment text",
  includeTimestamp: true,
  includeSvgFilename: true
});
```

## How It Works

### Architecture

```
SVG File
   ↓
svg-parser
   ↓
emits 'gcode:generated' event
   ↓
[G-Code Commenter intercepts]
   ↓
prepends comment
   ↓
emits 'gcode:modified' event
   ↓
G-Code Editor receives modified code
```

### Event Flow

1. **svg-parser generates g-code** and emits `gcode:generated` event
2. **G-Code Commenter subscribes** to this event
3. **Event is filtered** to ensure it's from svg-parser
4. **Comment is prepended** to the g-code string
5. **Modified event is emitted** as `gcode:modified`
6. **Downstream listeners** receive the modified g-code

### Key Technical Details

- Uses RxJS observables for event streaming
- Non-blocking async operations
- Automatic cleanup on deactivation
- Configuration hot-reloading

## Troubleshooting

### Comment Not Appearing

**Possible causes:**
- Extension is disabled → Enable in Extensions view
- Event not being emitted → Check svg-parser is working
- Event name mismatch → Verify event names match

**Debug steps:**
1. Check extension is enabled
2. Open browser console
3. Look for log messages: "G-Code Commenter: Listening for svg-parser events"
4. Parse an SVG and watch for: "G-code comment prepended successfully"

### Original G-Code Modified

The extension should ONLY prepend a comment. If other modifications occur:
1. Disable the extension
2. Test if issue persists
3. Report bug with example SVG

### Performance Issues

The extension uses efficient event streaming and should have minimal impact. If you experience slowdowns:
1. Disable `includeTimestamp` and `includeSvgFilename`
2. Check browser console for errors
3. Try disabling the extension temporarily
